# filters: notes for AI coding agents

`javaabu/filters` is a Laravel package: filters and sorts for index pages. Each filter defines its javaabu/stencil fields, the query parameters it reads and what it does to an Eloquent query; `Filters` reads the URL, applies the filters and sort, and renders the filter bar, chips and sort controls in Blade (javaabu/forms v2) or Inertia React (`resources/js`, imported by apps as `@javaabu/filters` through javaabu/manifest).

## Layout

| Path | What |
| --- | --- |
| `src/Filters.php` | The root: definition, input, values, sorts, apply, URLs, chips, form, rendering, JSON |
| `src/Filter.php` | The base filter (and custom filters): fields, query keys, value cleaning, apply, chips |
| `src/*Filter.php` | The types; `RangeFilter` is the base of the date and number ranges |
| `src/Sort.php`, `src/Chip.php` | A sort, an applied-filter chip |
| `src/Fields/FilterSelect.php` | The stencil select the select filters render (no `sync_` field, selected labels for ajax) |
| `src/Support/Dates.php` | Strict date parsing and chip formatting |
| `resources/views/components/` | `<x-filters::bar>`, `chips`, `sort`, `heading`; `render.blade.php` is `{{ $filters }}` |
| `resources/js/` | `FilterBar`, `FilterChips`, `SortSelect`, `SortableHeading`, `types.ts` (the JSON format), `form.ts` |
| `tests/` | PHPUnit (`Unit`, `Feature`, `Fixtures`) and Vitest (`tests/js`, with fixtures generated by `JsFixtureTest`) |
| `docs`, `llms.txt`, `resources/boost` | Docs, the index for assistants, the Laravel Boost guideline and skill |

## Rules

- Follow the Javaabu PHP guidelines (`vendor/javaabu/boost-javaabu-guidelines`): snake_case variables and properties, camelCase methods, `#[Test]` methods named `it_…`, early returns, no `else`.
- The query-string format is flat and matches javaabu/forms (`orderby`/`order`, `search`, `per_page`). Invalid input is ignored, never thrown. Only registered sorts are applied.
- `Filters` must stay `Htmlable` but not `Stringable`: Blade casts `Stringable` component attributes to strings, which renders the bar recursively.
- URLs are built in PHP and sent in the JSON; the React components don't build query strings.
- A change to the JSON changes `resources/js/types.ts`, `docs/advanced-usage/json-format.md` and the components together. Then run `FILTERS_UPDATE_FIXTURES=1 vendor/bin/phpunit --filter JsFixtureTest` and commit `tests/js/fixtures`.
- The React code imports `@javaabu/stencil` from `vendor/javaabu/stencil/resources/js` (tsconfig paths, vitest alias), so run `composer install` before the JS tooling.
- Every user-facing string goes in `lang/en` and `lang/dv` (and `getStrings()` for React); tests use Thaana for user-facing behaviour. Views use logical utilities only.
- Every change needs tests, docs (linked from `llms.txt`), the Boost skill if it changes usage, and a line in `CHANGELOG.md`.

## Commands

```bash
composer install && pnpm install      # pnpm 10.28 (packageManager)
composer lint && composer test        # Pint and PHPUnit
pnpm lint && pnpm format:check && pnpm typecheck && pnpm test
```
